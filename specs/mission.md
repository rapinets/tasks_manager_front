# Місія проєкту: Tasks Manager - фронтенд

## Що ми будуємо

Односторінковий клієнт (SPA без роутингу) для Tasks Manager API.
Дозволяє переглядати, фільтрувати, додавати, редагувати та видаляти
проєкти з його завданнями та самі завдання в проєкті.

## Технологічні обмеження (діють для ВСІХ ітерацій)

- Тільки vanilla HTML, CSS, JavaScript. Без фреймворків і бібліотек,
  без білд-інструментів (npm, webpack, vite тощо).
- Рівно три файли: index.html, style.css, app.js у корені проєкту.
  Кожна ітерація редагує ці самі файли, а не створює нові.
- Запити до API - тільки через fetch(). Базова адреса:
  https://tasks-manager-back.onrender.com

## API, з яким працюємо (повний контракт, для довідки в будь-якій

## ітерації)

Для проєктів(projects)
- POST /projects/ - тіло: {name, description}. 201, 422.
- GET /projects/?limit=&offset= - список проєктів.
- GET /projects/{id} - одн проєкт. 404, якщо не знайдено.
- PATCH /projects/{id} - часткове оновлення. 404, 409.
- DELETE /projects/{id} - видаленні проєкту всі дочірні задачі видаляються автоматично (ondelete="CASCADE"). 204, 404.
- POST /projects/{id}/tasks - Список пов'язаних задач. Забезпечує двосторонній зв'язок (реалізує зв'язок One-to-Many з сутністю Task); тіло: {title, description, priority, due_date}. 201, 422.

Priority - один з: low, medium, high.

Для завдань(tasks)
project: Зв'язок із батьківським проєктом (реалізує зв'язок Many-to-One)
- GET /tasks/{id} - показати одне завдання(task)
- PATCH /tasks/{id} - часткове оновлення. 404, 409.
- DELETE /tasks/{id} - видалення. 201, 404

## Як ми працюємо: ітеративний Spec-Driven Development

- Весь фронтенд не описується одним величезним технічним завданням.
  Ця місія (mission.md) фіксує те, що НЕ змінюється між ітераціями
  (мета, обмеження, API), а roadmap.md - впорядкований список
  невеликих ітерацій (фіч).
- Кожна ітерація має власний вузький spec.md: що саме додається
  зараз і що свідомо НЕ входить у цю ітерацію (щоб ШІ не забігав
  наперед).
- Реалізуємо, перевіряємо і закриваємо одну ітерацію - і лише тоді
  переходимо до наступної. Код попередніх ітерацій не переписується
  без потреби.
- mission.md майже не змінюється. roadmap.md і spec.md конкретної
  ітерації - робочі документи, які оновлюються по ходу проєкту.
